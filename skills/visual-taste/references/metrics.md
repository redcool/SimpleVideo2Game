# 指标定义、公式与校准

## 一、口径（所有工具一致）

- **统计宽度**：解码后统一缩到 320 px 宽，再算。指标看分布，不看分辨率。
- **亮度**：Rec.601，`Y = 0.299R + 0.587G + 0.114B`（0–255）。人眼对绿色更敏感，所以不是三通道平均。
- **艳度**：HSV 的 S，`S = (max - min) / max`（0–1）。
- **色相**：只统计 `S > 0.15` 的像素。灰色没有色相，硬塞进 0° 会污染直方图。
- **主色分箱**：每通道压到 4 bit（16 级）后计数，取箱内均值作为该色 hex。与上游 `study_video.py` 同口径。
- **暗/中/亮分区**：`Y < 64` / `64 ≤ Y < 186` / `Y ≥ 186`（约 25% 与 73%）。
- **纯黑/纯白**：`Y ≤ 8` / `Y ≥ 247`。这两个数高，画面就有"贴片感"。
- **对比**：亮度 P95 − P5。用分位数而不是最大最小，避开单个高光像素。
- **熵**：32 格亮度直方图的香农熵（bit）。全黑画面接近 0，复杂画面接近 5。
- **细节量**：相邻像素亮度差的平均绝对值 ÷ 255。不含正负抵消，所以和"清晰度"相关，但不是锐度。

## 二、公式

```text
mean_saturation            = 平均(S)
palette_concentration_top5 = 前 5 个主色的 share 之和
contrast_p95_minus_p5      = P95(Y) - P5(Y)
shadow/mid/highlight       = 各区像素数 / 总像素数
pure_fraction              = (纯黑 + 纯白) / 总像素数
luma_entropy_bits          = -Σ p·log2(p)，p 为 32 格亮度直方图概率
edge_density               = mean(|Y[x+1,y]-Y[x,y]|, |Y[x,y+1]-Y[x,y]|) / 255
层级 luma_gap              = |mean(Y 主体框) - mean(Y 框外)|
层级 saturation_gap        = |mean(S 主体框) - mean(S 框外)|
```

## 三、起步阈值（quiet / vivid）

见 `scripts/palette_report.py` 的 `COLOR_PROFILES` 与 `scripts/frame_metrics.py` 的
`STRUCTURE_TARGETS`。**阈值写在代码里，不写在感觉里**：要改就改表，并在提交信息里说明为什么。

| 指标 | quiet | vivid |
|---|---|---|
| mean_saturation | 0.12–0.45 | 0.30–0.75 |
| contrast_p95_minus_p5 | 30–165 | 40–175 |
| palette_concentration_top5 | 0.25–0.95 | 0.22–0.95 |
| highlight_fraction | 0.02–0.45 | 0.02–0.55 |
| shadow_fraction | 0.02–0.55 | 0.01–0.45 |
| luma_entropy_bits | 2.5–4.8 | 3.0–5.0 |
| edge_density | 0.006–0.045 | 0.008–0.06 |
| pure_fraction | 0–0.06 | 0–0.08 |
| 层次 | 亮度差 ≥ 25 或饱和度差 ≥ 0.15 | 同 |

**校准依据（2026-11-12 实测）**：取上游 31 个成品游戏的并排图，切出参考半边与游戏半边各一张量。
结果是 `mean_saturation` 0.23–0.24、`contrast` 116–148、`palette_concentration_top5` 0.33–0.35、
`luma_entropy_bits` 3.7–4.1、`edge_density` 0.010–0.017。第一版阈值（对比 ≤110、集中度 ≥0.45）
把参考自己判成了出界，于是按实测放宽——**阈值要能容下你自己的参考，否则它只是在测你的偏见**。

## 三·补：比差值比比区间更可信

```powershell
python palette_report.py 参考帧.png --json > 参考.json
python palette_report.py 成品帧.png --baseline 参考.json --strict
```

同一套指标、同一条命令，输出 `参考 / 当前 / 差 / 容差 / 判定`。
容差写在 `palette_report.py` 的 `DELTA_TOLERANCES`：饱和 ±0.06、对比 ±18、
集中度 ±0.10、高光 ±0.08、暗部 ±0.08、熵 ±0.35、细节 ±0.008、纯色 ±0.03。

真实例子（天空场景，参考 vs 成品）：高光占比 **0.32 → 0.76**（+0.44）、对比 148 → 116、
熵 4.10 → 3.70 → 结论是"成品整体发白、天空过曝"，而不是一句"感觉不对"。

## 四、怎么校准（三步）

1. **先量你的参考**：`palette_report.py 参考.mp4 --json`，把它当作本项目的"真值"。
2. **量三张你认可的成品**，取三者的交集，作为项目区间；与上表差太多就改表。
3. **记录两次**：改前 / 改后的数字写进项目的验收记录。数字往回走就是改错了，
   不要用"我觉得更好"覆盖它。

## 五、常见误判

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 饱和度低但画面并不灰 | 大面积中性色背景 + 小面积高饱和主体 | 看层次，不要硬拉饱和 |
| 熵高但画面很空 | 颗粒/噪点多 | 看 edge_density 与纯色率，先降噪 |
| 对比高但看不清主体 | 背景和主体都高对比 | 看层次与色相分布，靠**色相/明度分离**而不是加大对比 |
| 主色集中度极高 | 画面单调或过曝 | 先看 highlight_fraction，再决定加层次还是减曝光 |
| 数值全绿但难看 | 构图、故事、可读性不在指标里 | 回到并排图与录像，人做最终判断 |
| 把并排图当单帧量 | 并排图有两个世界 + 白边 | 先切半（`ffmpeg -vf crop=iw/2:ih:0:0`）再量 |
