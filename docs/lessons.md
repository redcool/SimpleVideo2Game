# 经验与教训（交给下一部作品）

这份文档只记"踩过才知道"的东西：**哪些指标会骗人、哪些参数必须显式、哪些顺序不能反**。
每条都带数字或复现路径，可以直接抄进下一部第三人称动作游戏的前期准备。

---

## 一、量化验收的三次翻车（指标比人眼笨）

### 1. 暗场画面的"饱和度"是假的

- 现象：一条几乎全黑的片段（主色 `#070503`）报出 `mean_saturation = 0.403`。
- 原因：`S = (max-min)/max`，RGB(7,5,3) 的 S = 0.57。近黑像素用极小差值算比率，天然虚高。
- 修法：只统计 **V ≥ 0.10** 的可见像素，并输出 `visible_fraction` 让口径可见。
- 影响：修正后"中文视频过饱和"的差距从 0.403 vs 0.218 收到 0.375 vs 0.213；
  "饱和绿版越界"这个结论其实是 bug 造出来的。

### 2. 320 宽看不见结构

- 现象：给站台补了 8 根立柱、26 个屏蔽门框、安全线、广告灯箱，`edge_density` 只从 0.0118 涨到 0.0140。
- 原因：所有指标都先把画面缩到 320 宽（为了快与跨分辨率可比），小于 1/320 屏宽的细节被平均掉。
- 结论：**指标管配色与明暗，人眼管结构与完成度**。验结构要出原分辨率局部裁切（1024×612）。

### 3. 胶片颗粒被当成"运动"

- 现象：去掉画面颗粒后，同一条路线的"最活窗口"分数从 0.0751 掉到 0.0245（3 倍）。
- 原因：`rank_take` 用 ffmpeg 的 `scene` 分（逐像素帧差），颗粒就是高频帧差。
- 修法：先 `scale=160:-2` 再算 scene 分；修正后 take_01 0.0191 vs take_02 0.0187，终于可比。

**共同点**：这三个错误都让"数字看起来合理"，然后把我引向错误结论。**验收工具也要被验收。**

## 二、音频：三个必须先搞清楚的概念

### 1. 接缝要量"样本跳变"，不是"两段是否相似"

- 错误实现：比较首尾各 100 ms 的波形相似度。噪声类音效永远不相似，于是给出 0.40 的假失败。
- 正确做法：量"最后一帧 → 第一帧"的**样本跳变**（占整段峰值比例），阈值 0.15。
- 还有两个坑：①必须在**原生采样率**上量（8 kHz 降采样的边界补零会把跳变从 0.02 放大到 0.24）；
  ②归一化基准要用**整段峰值**，用窗口峰值会把小信号处的跳变放大十倍。

### 2. 瞬态音效到不了 −16 LUFS

- 1 秒的落地/火花音，峰值顶到 −1.5 dBTP 之后，响度往往只有 −19 ~ −26 LUFS。
- 追 −16 就会削顶。**瞬时音效在混音里靠峰值被听见，不靠 LUFS**。
- 所以 `sfx` 档的响度区间是 **−26 ~ −13**，不是广播标准。

### 3. 铺底音不该要求动态

- 30 秒 drone 套 `music` 档会因 LRA < 2 判失败——那是设计意图，不是缺陷。
- 单开 `drone` 档：只看峰值与响度，不看 LRA。

### 4. 循环音效的修复顺序不能反

- 先 `loudnorm` 再交叉淡化 → 时变增益让接缝又跳 0.35。
- 正确顺序：**先交叉淡化，再用静态增益**追目标响度。

## 三、3D 管线：两个会导致"跑不动"的坑

1. **减面必须"先重网格再减面"**：Hunyuan3D 出的体素网格由很多小壳组成，
   只用 Blender Decimate 会卡在 3.6 万面（每个壳保留最低面数）；先 Voxel Remesh 再 Decimate → 12,000 面。
2. **贴图不是体积主因**：512 JPEG 只占 85 KB，GLB 从 0.9 MB 涨到 1.24 MB 是 UV 与几何带来的。
   想压体积，压几何；别指望压贴图。

另外：`ImageOnlyCheckpointLoader` 要**单文件** checkpoint（`hunyuan_3d_v2.1.safetensors`），
不是 `diffusion_models` 里拆开的 dit/vae；用错了会报缺 CLIP vision。

## 四、实时渲染 vs AI 静帧：动态范围追不上，别硬追

- AI 静帧的 `highlight_fraction` 可以到 0.072（7% 像素亮度 ≥ 247），那是"过曝高光 + 死黑"的产物。
- Three.js 走 ACES 色调映射时，纯白只映射到 212 左右，**大面积 247 以上根本到不了**。
- 关键技巧：光源材质加 `toneMapped: false`，让灯管保持原始高亮（否则怎么调曝光都不算高光）。
- 追不上的部分不要靠拉曝光硬凑：会丢掉暗部。记成已知差异，写在 SPEC 里。

## 五、提示词：语言按模型分，物理量必须写

- **图像（H3 image / MOSS / Ignis）：中文更强**。同场景同 seed：细节 +10~16%、对比 +21%、
  Ignis 从灰图（饱和 0.060）回到 0.155。
- **H3 视频：用英文**。中文会把整张画面染色（饱和 0.375 vs 0.213），去颜色词只降 0.019，压不住。
- 不管哪种语言，**光要写成物理量**（位置、色温、照度、软硬、衰减），材质写成物理属性（粗糙度/金属度/SSS）。
- 把 hex 色值写进提示词就是调色：`#7fbf7a` 会让 MOSS 绿过头；想要克制就写 `淡绿 #9fb79a`，
  并声明"只有灯是绿的，墙面保持中性灰"。

## 六、工程纪律：三条来自外部项目的对照

1. **长任务 job 化**：生成工具最多等一小段，没完就返回 job id，再 `wait_job`。
   本仓库实现为 `comfy_asset.py --detach` / `--collect <id>`；背景是一次 H3 视频撞上调用方 600 s 上限被杀，
   成品还在 ComfyUI 里但客户端已死。
2. **参数必须显式生效或显式报错**：ComfyUI 对未知输入要么忽略、要么运行时才报错。
   现在 `--set 5.nonexistent=1` 会直接告诉你"该节点现有输入：clip, height, prompt, vae, width"。
3. **公开契约固定**：工作流文件名与节点 id 就是公开工具表，改名要版本化 + 测试断言。

## 七、环境里最容易白撞的几件事

- **本机不能用 venv 里的 torch**：RTX 5090 需要 cu130，GPU 计算只归 ComfyUI 自带的 Python。
- **写长 PowerShell 单行命令容易撞墙钟**：一次 H3 批量生成被 600 s 截断；批量任务要么 `--detach`，要么分批。
- **编辑代码要按实际行内容匹配锚点**：凭记忆写锚点导致替换没生效，下游却已引用新变量 →
  整帧循环抛错、角色不动（`scanConeLayers is not defined` 就是这么来的）。
- **`.gitignore` 的 `*.glb` 会悄悄吞掉素材**：说"已入库"前必须 `git ls-files` 确认，或干净 clone 验证。
